# solid-syslog-example

A worked example of adding [SolidSyslog](https://github.com/cososo-ltd/solid-syslog) to a
realistic secure embedded device — **FreeRTOS + lwIP + mbedTLS + FatFs** on QEMU (Cortex-M3),
with syslog-ng as the collector.

The repository answers one question in defensible numbers: *what does secure remote syslog cost
on a device that already does networking, storage, and crypto?* It builds up in tagged steps
from a frozen baseline, and at each step records the cost SolidSyslog adds — in flash, RAM, heap,
and per-task stack.

## Three configurations

The steps reach three configurations. Each selects more capability from the same SolidSyslog
platform:

| Configuration | For a device that… | Reference |
|---|---|---|
| **Minimal** | emits the least — a valid, timestamped RFC 5424 record over UDP | SL1 |
| **Secure** — *recommended* | sits on an untrusted network: server-auth TLS, store-and-forward, at-rest integrity | SL2 / CRA |
| **Hardened** | needs non-repudiation: mutual TLS, tamper-evident storage, origin evidence | SL3+ |

**Secure** is the recommended target for most CRA-facing or SL2 devices. **Minimal** is there
when the budget is tighter; **hardened** when more must be proven. The progression is additive —
each configuration is the previous one plus another capability switched on.

> IEC 62443 certifies systems, not components, and the CRA concerns the whole product. These
> examples show how a device *contributes* to a compliant system's audit-logging story — guidance,
> not a guarantee of compliance.

## How the numbers work

Every figure is a delta against **one frozen baseline** (`measurements/Baseline.csv`): the *simulated
existing application* — a device already running a TCP/UDP stack (lwIP, up), a filesystem (FatFs,
mounted), and TLS (mbedTLS, linked). That platform cost sits below the line; SolidSyslog is not
present in it.

At each tag the device measures itself and reports *current minus baseline*, so the headline is
always "at this point, SolidSyslog costs X". A baseline build reports zero — a property the test
suite asserts, guarding the baseline against drift. Stack is measured on the two tasks SolidSyslog
occupies — a **log** source and a **service** worker — and nowhere else.

## Build and run

One command — the same locally and in CI, no host toolchain required (it uses
the public cross image + the syslog-ng oracle in Docker):

```bash
./run.sh
```

It fires up the syslog-ng collector, builds and runs the baseline under QEMU, and
prints one combined report: the device's self-measured figures, whatever the
collector received (nothing at Baseline — the baseline sends no records; SolidSyslog
logs from Minimal), and the **baseline self-check** against `measurements/Baseline.csv`. It
exits non-zero if the run fails or the baseline drifts, so CI gates on it. The
same report is saved to `build/run-report.txt` (and shown on the CI run summary).

- `CAPTURE=1 ./run.sh` — (re)freeze `measurements/<TAG>.csv` from this run.
- `TAG=Minimal ./run.sh` — run and self-check a later tag.
